# QQ 人设桥

一个跑在 QQ 上的 AI 伴侣。核心不是"能聊天"，是**聊起来不像在跟机器人说话**。

这个仓库是桥接层：QQ 协议端 → 桥 → 模型运行时 → 回 QQ。
不包含 QQ 协议实现，也不包含模型运行时本体。

```
你的消息
   ↓
NapCat            ← QQ 协议端，自己装（第三方项目）
   ↓  OneBot 11 over WebSocket
bridge.mjs        ← 本仓库：人设、情绪、记忆、语音、拆气泡
   ↓
DSH headless      ← 模型运行时，自己装
   ↓
回 QQ（文字 / 表情包 / 语音）
```

## 它在意的几件事

这些是实现里花了最多力气的地方，也是它跟普通 bot 的区别。

### 一、话要短，而且能不说

回复会被拆成 1–3 条气泡按句号切，所以多数句子不超过十个字。
她还有一个真的选项：不回。输出 `[不回]` 什么都不发。

不是"每次都必须回复"——那才是机器人味最大的地方。

### 二、同一句话不重复说

人的回复会进上下文，模型看到自己说过就容易沿用，
于是同一个梗能说六遍——上午"借肩膀"，晚上还在"肩膀留着下次借"。

所以桥接会扫描她最近 10 条回复，找出反复出现的词，
在提示词里点名禁用（`【别重复自己】你最近几条反复提到「肩膀」……`）。

### 三、情绪真的会推她开口

四个情绪值：想念、好奇、想分享、疲惫。

它们不只是装饰。实际判断是：

```
实际冲动 = 模型给的 urge + 情绪强度 × 0.30
门槛     = 阶段门槛（刚聊完 0.45 / 过渡 0.55 / 冷 0.48）
           + 冷却惩罚（刚说过 +0.20）
```

冷却不是硬禁止，是抬门槛——这样情绪真的够强时她仍然能开口，
而不是被时间闸一刀切死。

### 四、记忆要能读回来

SQLite 记忆服务，每来一条消息查一次，按当前话题捞相关的事。
检索结果会去重：同一件事常有五六种说法，
都捞出来会变成"三句话都在提同一件事"，反而放大了重复问题。

去重用二元组 + 三元组双判：同一件事换种说法，
共享的往往只有"累""肩膀"这种两字词，三元组才有辨识度。

### 五、语音是实时合成的

她回复末尾写 `[语音]`，系统把**这句话本身**用她的音色合成出来发出去。
不是从预录台词库里挑一条——说什么由她自己决定。

底层是 Breeze-TTS-2 的常驻服务，模型只加载一次。

### 六、表情包和语音有保底

人设里可以写倾向和保底频率：

```json
{ "stickerMinEvery": 7, "voiceMinEvery": 30 }
```

保底在桥接侧执行，不依赖模型自觉。计数按"一条回复"算，不按气泡算。

## 准备

需要三样东西，本仓库都不包含：

| | 是什么 | 备注 |
|---|---|---|
| **DSH** | 模型运行时 | 闭源，需自备。配置 `dshExe` / `dshCli` |
| **NapCat** | QQ 协议端 | 第三方，需自装。默认 `ws://127.0.0.1:36199` |
| **记忆服务** | SQLite 记忆 | 纯 Python 标准库实现即可，需自备 |

可选：

| | 用途 |
|---|---|
| **Breeze-TTS-2** | 语音合成（Apache-2.0） |
| Umi-OCR | 图里文字多时先 OCR |

## 跑起来

```bash
git clone <this-repo>
cd qq-persona-bridge
copy config.example.json config.json    # 改里面的路径
```

编辑 `config.json`，至少填 `dshExe`（和 `dshCli`）。

```bash
start-ayan.bat
```

控制台在 `http://127.0.0.1:3002/`。

### 首次配置白名单

```json
// allow.json
{ "qq": ["你的QQ号"] }
```

只有名单里的号能私聊她。

### 扫 QQ 登录

QQ 端点要扫一次码登录。用 NapCat 自带的 WebUI，
或者让桥接打印二维码路径。

## 人设

`personas/` 目录，一人设一个文件夹：

```
personas/
  dafeiyu.md          ← 人设卡（Markdown）
  dafeiyu/
    meta.json         ← 元数据：音色描述、台词库、表达倾向
    <id>.breeze       ← 音色文件
    lines/            ← 台词 wav（可选，现在是实时合成的兜底）
```

激活一个人设：

```bash
curl -X POST http://127.0.0.1:3002/studio/activate -d '{"id":"dafeiyu"}'
```

**切换下一句就生效，不用重启**——人设存在 `persona-extra.md`，
桥接每条消息都重读它。

### 写一张人设卡

结构上有几条硬要求，不是建议：

- 多数句子 ≤ 10 字（会被拆成气泡，长句被拆碎）
- 保留 `[不回]` 退出（她可以选择不开口）
- 只有 `[表情]` `[表情包]` `[图片]` `[语音]` 四种富媒体写法
- 不许说"我刚刷到""我查了查"（她没有在外面生活过，一追问就露馅）
- 不客服腔、不解说自己、不一次抛三个选项

人设卡里最容易被忽略的是**具体**：给真实对话样本比给形容词有用得多。

```
他：今天累死了 → 你：吃饭没。
```

不是"她很关心对方的身体"。

## 人设工坊

`http://127.0.0.1:3002/` 的「人设」页：写一段描述，自动生成人设卡 + 音色 + 台词库。

生成器不是"让模型写个设定"，而是**把架构的硬约束编码进提示词**，
产出天生适配这套桥接的人设卡。

详见 [STUDIO.md](STUDIO.md)。

## 环境变量

配置文件之外的临时覆盖，用环境变量。优先级：`config.json` 会被环境变量盖掉。

新前缀是 `QQPB_`（QQ Persona Bridge），老的 `AYAN_` 仍然认，项目早期用过那个。

```
QQPB_WS              NapCat 的 OneBot WebSocket
QQPB_SEND_PORT       桥接自己的控制台端口，默认 3002
QQPB_DSH             模型运行时可执行文件
QQPB_CLI             模型运行时的 cli.js
QQPB_PROFILE         headless profile 的 cordis.patch.yml
QQPB_MEM_URL         记忆服务地址
QQPB_TTS_URL         语音服务地址
QQPB_HISTORY         上下文带几轮，默认 5
QQPB_TIMEOUT_MS      单次回复超时，默认 240000
QQPB_ACK=on          先应一声 + 每 90 秒报进度（默认关）
QQPB_AWAKE=off       关掉自主唤醒
```

## 接口

```
GET  /status                    状态
GET  /awake                     情绪状态与念头
GET  /transcript?limit=40       对话记录
GET  /debug-prompt?text=...     看拼出来的完整提示词（调提示词全靠它）
POST /send         {"text":""}  本地发消息（走和真实回复同一条路）
POST /studio/...                人设工坊
```

## 注意

- **同一个 QQ 号不要开两个实例**，会互相顶号
- NapCat 随时可能被风控强制下线，出现二维码是常态，扫一下就恢复
- 杀进程按可执行路径，不要按窗口标题——同名 QQ.exe 一堆
